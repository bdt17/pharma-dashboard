BUG FOUND ALONG THE WAY (PR #150, merged): every Stripe*Sync service and
StripeBilling.available_plans / available_addons / single_packet_price
called Stripe::Price.list / Stripe::Product.list with no limit, so
Stripe silently capped results at its default page size of 10. The
account now has 13 active Prices, and "Extra Compliance Packet" ($149)
landed at position 11 -- past the cutoff. That Price backs both the
Billing page's addon-purchase button and
StripeBilling.single_packet_price, which overage billing (#140) uses to
bill a Starter/Pro org that opts in and exceeds its allowance;
single_packet_price raises NotConfigured when it can't find the Price,
so overage billing for any opted-in org was actually broken in
production, not just a missing upsell button. Fix: limit: 100 on every
Price/Product .list() call (Stripe's own per-page max, comfortably
above current scale). 540 tests still green, rubocop clean.

SECOND BUG, FOUND BY ACTUALLY CLICKING THROUGH THE BILLING PAGE AFTER
#150 DEPLOYED (PR #152, merged): fixing the pagination bug made a
previously-hidden-by-accident problem visible instead of invisible.
BillingController's plan list only rejected Prices explicitly tagged
tier=<a contact-sales tier> -- anything untagged passed through by
default. Two things were untagged: the abandoned "Pharma Transport Pro"
experiment (rendered as a real $200/mo Subscribe button on the actual
Billing page) and, more seriously, Enterprise's annual Price (Stripe
Price.create for an annual variant never carried metadata over from its
monthly sibling), which meant Enterprise -- deliberately contact-sales
only, see #138 -- was self-serve subscribable via annual billing,
bypassing the sales conversation entirely. Fix: BillingController now
allow-lists @plans against SubscriptionPlan.self_serve tiers instead of
rejecting by name, and StripeAnnualPriceSync copies the monthly Price's
tier tag onto the annual Price it creates. Mitigated live the same day
via the Stripe API (no deploy needed for the immediate fix): tagged
Enterprise's annual Price, then once the code deploy revealed the same
gap for Starter/Pro/Compliance's own (pre-existing, untagged) annual
Prices, tagged those three too. Verified end-to-end on the live Billing
page afterward: Starter/Pro/Compliance show monthly + annual Subscribe,
Enterprise shows only "Talk to us," the orphan is gone, and all three
addons (White-Glove, 10-pack, single packet) render. 542 tests green
(2 new: annual-tier-copy behavior, and a regression test reproducing
the exact leaked-Subscribe-button bug), rubocop clean.
